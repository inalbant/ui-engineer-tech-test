# Decisions

## Part 2: Migration

- Trade clicks open a 460px right-hand panel beside the list, following the composition in the supplied Lattice screenshots. The list and active detail tab scroll independently; the detail header and tab bar remain visible. The trades workspace uses the available width; the app header and assistant layouts are unchanged. At 900px and below, the detail panel takes the workspace width and the list is temporarily hidden. Panel width and breakpoint are local responsive choices, not measured reference values. This preserves the desktop table context at the cost of less table width; horizontal overflow stays within its frame. On small screens, inspecting the table and detail requires switching between them.
- The selected trade is stored in the list URL as `?trade=<id>`, alongside existing status filters. Opening pushes one history entry; switching trades replaces that entry. Back/Forward restore panel state. Close, or Escape while focus is inside the panel, dismisses it using the opening list entry when available; otherwise it removes the trade parameter. A bookmarked panel therefore does not require a preceding list visit. Native history updates use Next’s existing search-parameter integration. Actual links retain `/trades/[id]` for new tabs and direct access, where the same detail content appears in a narrower standalone view with the same Emails and Notes tabs. Its back link retains query parameters.
- The panel is a non-modal complementary region. Opening focuses its close button; closing restores focus to the last clicked trade link when available. The desktop table stays interactive without a backdrop or focus trap. Selecting a different trade resets the note draft so it cannot be accidentally submitted against another trade.
- The header follows the drawer’s heading-lg typography (18px/24px, weight 600, tight tracking), muted trade ID and compact two-column facts. Notional uses the shared currency formatter with an explicit currency-code label. The blotter lacks Arch’s action-summary data, so the counterparty remains its main heading; no synthetic suggestions, evidence or activity were added.
- Email messages use the reference’s compact sender/date typography, 8px frame radius, 12px inset and divided 13px/20px body. Kept the supplied message order, full bodies and existing recipient display; did not introduce message collapsing, replying or reference-only actions. Removed the 320px subject minimum and allowed long content and dates to wrap.
- Emails and Notes have separate counted tabs so notes are accessible without scrolling through every email. The header and tab bar stay above the scrolling active panel. The redundant “Trade details” toolbar is removed; close sits beside the trade identity and remains available during loading/errors. Tabs support arrow keys, Home/End, a single tab stop, selected state and associated tab panels. Both content panels remain mounted to preserve a note draft when switching tabs; changing trade resets the draft and returns to Emails. The direct detail page shares this tabbed content. The trade-off is that emails and notes cannot be read simultaneously. Drafts are not persisted across a completed close or reload, and changing trade discards the current draft without a confirmation prompt.
- Composed notes from the existing section, body, metadata, field and button patterns. Retained dispute-only entry, the 500-character limit, submission logic and error text. Added no new note workflow.
- Migrated Panel, EmptyState and Button to tokens. Panel sections now have programmatically associated headings. Button keeps its existing variant and size prop names, with migrated reference heights (24px small / 28px medium), hover/pressed overlays, disabled opacity and keyboard focus. Because it is shared, header and assistant buttons inherit these primitive styles; their layouts and behaviour were not redesigned.
- Badge has explicit outlined and subtle variants, both with a 6px radius. The trades table uses outlined badges; the detail header uses the filled subtle variant shown in the supplied drawer screenshot. Existing status-to-colour mapping and status text are retained; the reference’s reconciliation statuses are different product states. See audit finding 5.
- Replaced plain loading text with a token-styled status message, keeping navigation available: back on the standalone page and close in the panel. A failed or missing trade now shows an alert and retry action rather than a blank page. This is a small state-completeness addition to the migration, using the existing query’s refetch action.

## List refinements after review

I requested these refinements after reviewing the running app and asked Codex to implement them one at a time, pausing after each so I could demo the result.

- Made the table’s column headings sticky inside a table frame sized to the remaining workspace height. Rows scroll beneath an opaque header with a bottom divider; the title and filters remain above the table, and the detail panel scrolls independently. This keeps column context visible on longer lists.
- Status counts represent totals across all trades, independent of the table selection. A separate unfiltered RTK Query subscription supplies counts while the existing filtered query supplies rows; when no filters are selected, RTK Query shares the same cache entry/request. Unknown totals show “—” rather than zero. This prevents filtered results being mistaken for global totals without changing the API, at the cost of fetching the full list for totals on a filtered landing page. For this small dataset that is proportionate; a paginated product would need aggregate counts from the API.
- Moved the existing status control beside the Trades title in a compact, left-aligned toolbar, freeing vertical space for rows. The toolbar wraps when the list area narrows, and at 640px and below places the filters beneath the title; the filter segments can wrap within their own group. This adopts the reference’s compact toolbar composition while retaining the blotter’s multi-select filtering behaviour.

## Gaps and problems in the system

- The reference supplies drawer, facts, message, section and field patterns, but no direct counterpart for this combination of trade facts, emails and editable internal notes. Composed those patterns with Emails and Notes tabs without adding a component dependency. The tabs adapt the reference’s tab-bar pattern to the blotter’s existing data. Confirm panel width and responsive breakpoint.
- Retained the existing semantic status mapping; Arch’s reconciliation statuses do not map one-to-one to the blotter. Confirm the mapping before treating it as a shared product contract.
- The overall filter pattern, page heading hierarchy and pending filter results remain design questions in `AUDIT.md`. Generated tokens were not edited.

## Other things I noticed

- Note submission invalidates `Trades`, while the detail query provides `Trade`. A successful save may leave the detail note list stale until a refetch. This is a source-confirmed cache-tag mismatch, not a manually reproduced result; it deserves a focused follow-up.
- Note saving has no meaningful pending state and does not disable repeated submissions. Preserved for this styling migration; follow up with a pending label and duplicate-submission guard.
- The assistant still ignores the stream’s `done` marker and permits overlapping messages. The existing skipped WebSocket test and modal Dialog focus behaviour remain outside this migration. Dialog is not used on the detail page.

## Part 3: Finesse

- I moved the assistant’s message bubble styled component outside the render function, passed the message role through a styling prop, and replaced array-index keys with message IDs. Previously, each update created new component types, repeatedly remounting existing bubbles and triggering a hook-order error in development.

  I checked the change using React DevTools Profiler exports before and after. The recordings show repeated bubble remounting before the change and stable component identities afterwards; the hook-order error also disappeared. Median assistant render duration was similar (2.6 ms before, 2.5 ms after), with mixed results across other timing metrics, so I am claiming improved component stability and correctness rather than a demonstrated rendering speed-up.

- Added panel opening/closing motion after comparing the supplied reference. Desktop animates the workspace columns; the narrow-screen panel slides over the list. Both use the reference’s `--duration-slow` (240ms) and `--easing-standard`. The outgoing content remains mounted until transition end, with a computed-duration fallback for interrupted or zero-duration transitions. It is inert and hidden from assistive technology during exit; focus returns to the selected trade link. Reduced-motion CSS removes both transitions. A regression test covers retained/inert exit content and removal without a transition event. Browser computed styles confirmed 0.24s and `cubic-bezier(0.2, 0, 0.38, 0.9)`; opening/closing were exercised, but frame performance and OS reduced-motion mode were not measured.
